## Architecture and data

The existing GZCLP engine remains authoritative. The repository owns warm-up mutations and historical progression replay; composables only present persisted results and issue actions. Schema version 8 adds baseline progression fields to each session exercise for safe replay. `MIGRATION_7_8` preserves existing rows; old history without a trustworthy baseline produces a conflict rather than an inferred rewrite. Backup schema accepts versions 7 and 8. Actual completed sets are never rewritten by replay.

Primary files: `GzclpScreen.kt`, `GzclpViewModel.kt`, `GzclpOnboardingDraftStore.kt`, `GzclpRepository.kt`, `GzclpEntities.kt`, `GzclpDao.kt`, `GzclpRestNotification.kt`, `AppDatabase.kt`, `DatabaseModule.kt`, `NavigationHost.kt`, `MainScreen.kt`, `HomeScreen.kt`, `MainActivity.kt`, and `AndroidManifest.xml`. Tests are under `app/src/test/java/org/librefit/gzclp` and `app/src/androidTest/java/org/librefit/db`. Backup format details are in `docs/training-backup.md`.

## Verification

`JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home' ./gradlew :app:testDebugUnitTest :app:connectedDebugAndroidTest :app:assembleDebug --offline` passed on 2026-10-22 after the Settings recovery and large-font Progress fixes: 84 local unit tests, 13 device tests on Pixel 9, and debug APK assembly. `git diff --check` passed.

Observed on emulator: first launch; four-step setup using illustrative loads; Today A1; generated and completed warm-ups; 60 kg plate loading with a 20 kg bar; one-tap working sets; rest timer after app force stop; full A1 completion and correct squat 65 kg / bench T2 42.5 kg next prescriptions; Today advanced to B1; populated History, Progress, and Settings. Android's document picker exported a completed A1 workout and restored it after a unit change: the preview showed one workout and 11 logged sets, Today returned to B1 in kg, History retained A1, and squat's next T1 load remained 65 kg. See screenshots 21–22. These are runtime observations, not automated end-to-end tests. Large-font and dark screenshots cover onboarding only. Instrumented tests clear app data; runtime profiles used for screenshots were illustrative.

The failed-lift UI journey was verified across a full rotation: B1 Overhead Press missed the first 5×3+ set, completion explained the 6×2+ switch at 30 kg, and the next B1 after A2, B2, and A1 displayed 30 kg · 6×2+ (screenshots 23–25). Five completed sessions were visible in History (26). The historical-correction UI journey described above used this populated profile. The document picker exported a populated, versioned backup, restored it after a unit change, and preserved both History and the next workout.

Not yet verified end to end: a gesture-only TalkBack workout with spoken output. Emulator input and screenshots cannot prove what TalkBack speaks; this requires a human or audio-capable accessibility test. Onboarding draft restoration after a force stop was verified manually with a partially entered T1 load. Temporary and future substitutions were exercised in the emulator, including Undo; the completed-session substitution result and post-reset replay conflict are covered by device tests. Notification denial and grant were tested in Android settings.

## Run

Open the project in Android Studio and run the `app` debug variant, or build with the Gradle command above and install `app/build/outputs/apk/debug/LibreFit-debug.apk`. The application works offline and opens directly to GZCLP setup or Today.
